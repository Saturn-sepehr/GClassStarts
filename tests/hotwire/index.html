gclass-anims for Hotwire

Hotwire is Turbo and Stimulus together: Turbo drives page visits over the wire, Stimulus attaches behaviour to markup that never gets compiled. gclass-anims animates whatever is in the document, so the two coexist without either knowing about the other.

This page has no build step for its markup and no framework. The two libraries it does use are the same two a Rails app gets.

Get started

Quick start

Import initAnimations once your DOM is ready. From then on, everything is class-driven: add a utility class to an element and it animates - no per-element JS, no config files.

One call, on turbo:load

Turbo's own lifecycle event is the right hook, because a Drive navigation replaces the document and the engine needs a fresh walk. The page also calls start() directly, so a hard load that never goes through Turbo still initialises. 

// main.js
import '@hotwired/turbo'
import { Application } from '@hotwired/stimulus'
import { initAnimations } from 'gclass-anims'

document.addEventListener('turbo:load', () => {
  initAnimations()
})

    Class anatomy

    Class anatomy: behaviour (.spawn-up) + trigger (.scroll, .appear) + tunables (.time-1, .ease-back, .priority-2). Combine freely - order in class does not matter. 

    <!-- behaviour + trigger + tunables -->
<div class="appear scroll spawn-up">…</div>
<div class="appear scroll order ease-expo time-1 priority-2">…</div>
<div class="float">loops forever</div>
<button class="magnet click-expand">magnet + click</button>

    • Behaviour

      spawn-up, float, marquee, magnet

    • Trigger

      appear, scroll, preserve

    • Tunables

      order, ease-expo, time-1, priority-2

    Notes

    • turbo:load is the right hook, not DOMContentLoaded. A Drive navigation replaces the document, so the engine needs a fresh walk on every visit. That is Turbo's own lifecycle event and the page uses it as documented.
    • data-turbo-permanent is the preserve equivalent. The permanent badge above survives a navigation without being re-initialised, which is the same outcome .preserve buys on a framework that re-renders.
    • Two utility systems coexist here. The em-based .space-* / .text-* classes on this page are hotwired.dev's own. They set spacing and size; gclass-anims sets motion. Neither reads the other.
    • GSAP stays external. ESM is dist/gclass.esm.js and CJS is dist/gclass.cjs - GSAP is external, not bundled, and the build is tree-shakable with sideEffects: false.
