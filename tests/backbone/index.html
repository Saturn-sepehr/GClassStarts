gclass-anims for Backbone.js

Backbone splits data from UI: models own state, views re-render when it changes. gclass-anims animates whatever the view produced. Call initAnimations() once on ready - every view.render() after that is picked up automatically.

Get started

Install

GClass ships as the npm package gclass-anims. GSAP is a regular dependency and is installed automatically - nothing is bundled or redistributed. Backbone is a peer of this page, not a dependency of the library.

npm install gclass-anims backbone

Quick start

Import initAnimations once your DOM is ready. From then on, everything is class-driven: add a utility class to an element and it animates - no per-element JS, no config files.

Usage - on document ready

// main.js
import Backbone from 'backbone'
import { initAnimations } from 'gclass-anims'

document.addEventListener('DOMContentLoaded', () => {
  initAnimations()

  new AppView({ el: '#app' }).render()
})

Live - a Backbone.View rendering a collection

The button calls collection.add(), which fires the collection's "add" event, which re-renders the view. Every row that render inserts carries .appear and animates - no re-initialising.

0 models 
const RowView = Backbone.View.extend({
  tagName: 'li',
  className: 'appear spawn-up time-1 rounded-lg border border-line bg-panel p-4 font-mono text-[13px]',

  render() {
    this.$el.text(`row ${this.model.get('n')} - rendered by Backbone.View`)
    return this
  },
})

// collection "add" -> view re-renders -> MutationObserver picks the row up
this.listenTo(this.collection, 'add', () => this.render())

Class anatomy

Class anatomy: behaviour (.spawn-up) + trigger (.scroll, .appear) + tunables (.time-1, .ease-back, .priority-2). Combine freely - order in class does not matter.

// behaviour + trigger + tunables
<div class="appear scroll spawn-up">…</div>
<div class="appear scroll order ease-expo time-1 priority-2">…</div>
<div class="float">loops forever</div>
<button class="magnet click-expand">magnet + click</button>

Behaviour

spawn-up, float, marquee, magnet

Trigger

appear, scroll, preserve

Tunables

order, ease-expo, time-1, priority-2

Notes

  • One ready call. initAnimations() runs once, before the first render. Re-renders replace innerHTML, and the engine treats every new node as a fresh mount - which is exactly what a Backbone view does.
  • Re-renders replay. A render() that swaps a subtree rebuilds the elements, so .appear plays again and .scroll re-measures. Put .preserve on anything that should survive a re-render - the header and nav.
  • GSAP stays external. ESM is dist/gclass.esm.js and CJS is dist/gclass.cjs via vite.lib.config.js - GSAP is external, not bundled. The build is tree-shakable with sideEffects: false.
