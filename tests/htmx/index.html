gclass-anims for htmx

htmx swaps HTML fragments over the wire. gclass-anims animates whatever HTML is on the page, including the fragments. Call initAnimations() once - every hx-get, hx-post and hx-swap after that is picked up automatically, because a swap is just a batch of DOM insertions.

Get started

Install

GClass ships as the npm package gclass-anims. GSAP is a regular dependency and is installed automatically - nothing is bundled or redistributed. htmx is a peer of this page, not a dependency of the library.

npm install gclass-anims htmx.org

Quick start

Import initAnimations once your DOM is ready. From then on, everything is class-driven: add a utility class to an element and it animates - no per-element JS, no config files.

One call, on DOM ready

// main.js
import htmx from 'htmx.org'
import { initAnimations } from 'gclass-anims'

document.addEventListener('DOMContentLoaded', () => {
  initAnimations()
})

Live - partials swapped in by htmx

Nothing re-initialises after this point. The rows below arrive as an HTML partial over fetch, and each one plays its entrance because the engine watches the DOM for insertions. No htmx:afterSwap handler is involved, and none is needed.

loading… 
<button hx-get="./partials/rows-1.html"
        hx-target="#rows"
        hx-swap="innerHTML">Load rows</button>

<!-- rows-1.html, fetched and swapped in -->
<div class="appear spawn-up time-1 card">row 1</div>

Class anatomy

Class anatomy: behaviour (.spawn-up) + trigger (.scroll, .appear) + tunables (.time-1, .ease-back, .priority-2). Combine freely - order in class does not matter.

<!-- behaviour + trigger + tunables -->
<div class="appear scroll spawn-up">…</div>
<div class="appear scroll order ease-expo time-1 priority-2">…</div>
<div class="float">loops forever</div>
<button class="magnet click-expand">magnet + click</button>

Behaviour

spawn-up, float, marquee, magnet

Trigger

appear, scroll, preserve

Tunables

order, ease-expo, time-1, priority-2

Notes

  • No afterSwap hook. initAnimations() runs once on DOMContentLoaded and every later swap is handled by the engine's MutationObserver. Wiring htmx:afterSwap to re-initialise would be the wrong instinct.
  • Partials carry the classes. The server response is plain HTML, so .appear and .scroll travel with the markup. Nothing in the partial is special beyond the class attribute.
  • hx-boost swaps replay. A boosted navigation replaces the body, so .appear plays again and .scroll re-measures. Put .preserve on anything that should survive a boosted swap.
  • GSAP stays external. ESM is dist/gclass.esm.js and CJS is dist/gclass.cjs - GSAP is external, not bundled, and the build is tree-shakable with sideEffects: false.
